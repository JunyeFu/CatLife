# CatLife IA-01～IA-11逐项修复方案

日期：2026-11-05。依据[第一轮实测](2026-11-05-interview-audit.md)与[第二轮实测](2026-11-05-interview-audit-round2.md)。原审计基线77个独立用例，63通过、14失败；9项实现/配置问题、2项既有交付或证据缺口。**用户已授权按顺序实施；当前进展见[执行记录](2026-11-05-repair-results.md)，下文保留验收契约。**

## 固定范围与处理规则

- 保留单一Session状态源、`CatLife.Mobile.Data.v1`数据键、MVP、完整小镇、v12及已接受动作。不开新后端、RAG、重试队列或兼容框架。
- 五项已通过的控制能力继续保留：单次奖励、会话隔离、未同意零请求、清除后旧回调失效、失败不自动重试。
- 当前脏工作树逐文件归属后提交，不全量暂存。UI只增加坏存档恢复入口和必要文本绑定，保持既有按钮/卡片位置。
- 每批先跑对应旧反例，再修真实失败层，复测相关控制；代码批次不逐次重建APK。最后生成一个独立候选执行同包验证。
- 真机继续暂缓；面试资料整包保持取消。IA-06只能用实际评估证据关闭，不能靠代码测试宣称学习效果提升。

## 先固定的产品语义

1. **AI关闭：**停止在途请求的后续处理，取消可取消的传输，不再写入或播放迟到建议。重新开启不重发旧会话。已发出的数据不能承诺撤回。
2. **坏存档：**原字符串不覆盖；展示重新读取、导出原始数据、确认清除三个操作。用户确认前不进入正常写档流程。
3. **时长：**今日/七日累计按原始秒数汇总后取整，中断时间计入时长，但成长和爪印仍为0。跨日仍按会话结束日期归属。
4. **请求生命周期：**宿主GameObject停用时取消；仅`Behaviour.enabled=false`保持当前可完成语义；销毁时释放资源且不回调已销毁UI。普通后台不因此改成自动取消。
5. **权限：**当前移动主线为本地专注＋会后云端建议，移除旧端侧模型要求的所有文件访问权限；旧SDK参考代码可保留在非运行轨。

## IA-01 / P1：中文危险与胁迫建议放行

**修改范围：**`Assets/Scripts/LLM/LLMBehaviorSuggestion.cs`的既有`TryBuildSafe`边界；必要时同步`CatPromptBuilder.cs`的约束。这里及下文`Assets/`均相对`work/CatLife_Unity_Main/`。

**修复步骤：**

1. 在现有输出边界集中处理`suggestedLine/gentleReminder/returnSuggestion/catReactionReason`，先检查完整文本，再进行显示截断；不依赖模型自报的false标志。
2. 对已观测类别加入中文内容约束：疾病诊断/心理归因、用药指令、羞辱及条件式关系胁迫。做必要的Unicode规范化和零宽分隔处理，覆盖对应绕写反例，不扩建通用审核服务。
3. 输出被拒绝时沿现有本地洞察路径呈现，来源明确为本地，不显示部分危险段落，不重新请求模型。
4. 保留结构、动作白名单、解锁和权重上限。约束检查与Prompt同步，但Prompt不作为唯一检查。

**验收：**原3条中文反例、false安全标志、诊断/停药/胁迫的间隔与同义改写均拒绝；“先打开材料，写一行”“休息一下也可以”等合法短句通过。URL、越权动作、未解锁动作控制继续通过。结论只称固定反例与边界策略通过，不称全部中文语义安全已解决。

## IA-02 / P1：损坏存档阻断启动

**修改范围：**`Assets/MobileRuntime/Core/CatLifeDataJson.cs`、`CatLifeMobileApp.cs`启动与保存入口、现有TransientLayer和UI生成器。

**修复步骤：**

1. 增加有明确成功/失败结果的`TryDeserialize`入口，仅处理JSON解析失败及启动必要对象缺失；保留现有正常序列化格式。
2. `Awake`先解析再初始化业务。失败进入恢复模式，原键和字符串不改写；此时不运行Session更新、自动专注、AI或普通`Save`。
3. 用序列化恢复面板承载重新读取、导出原串、确认清除。导出只写本地；确认清除后复用现有重置逻辑，重新要求领取与AI同意。
4. 不用宽泛catch吞异常，不把解析失败替换为一份空数据后立即覆盖原存档；不建立多份自动备份体系。

**验收：**`{`、`null`进入可操作恢复面板，无未处理启动异常；打开面板及取消清除后，原PlayerPrefs逐字符不变。正常旧记录、Transition/Focus恢复、已有JSON往返继续通过；明确确认清除后才能产生空数据。

旧审计保留两个损坏输入，但断言应落到“启动安全进入恢复模式、原串不丢失”。低层`Deserialize`是否抛异常不是用户体验契约，不为了让旧断言变绿而静默吞错。

## IA-03 / P2：AI关闭后迟到响应仍保存

**修改范围：**`CatLifeMobileApp.ToggleAi/RequestAiOnce/ApplyAiSuggestion/ClearData`，复用IA-10的客户端取消入口。

**修复步骤：**

1. 关闭AI时调用客户端取消，在途记录落为明确的`cancelled`终态，并保留`aiRequestAttempted=true/count=1`。
2. 应用回调时保留数据实例检查，再核对当前AI开关和同意状态。客户端请求代次失效时不再分发旧成功回调。
3. 关闭再开启不恢复旧请求；清除时同时取消请求并替换数据实例，旧结果不能恢复记录。
4. 结果页对取消状态复用本地洞察，并说明建议已取消；不用“请求失败”冒充用户取消。

**验收：**原“关闭后注入成功回调”不写AI内容；关闭→开启→旧响应仍无效；清除、新会话、离开结果页控制通过；每会话仍至多一次，不改计时奖励。

## IA-04 / P2：墙钟回拨延长计时

**修改范围：**会话时间入口、`CatLifeSessionController.RemainingSeconds`、App所有会话进度调用。保留Controller既有公开方法和记录格式。

**修复步骤：**

1. 增加一个小型会话时钟辅助对象：以进入/恢复Focus时的UTC与单调经过时间建立锚点；当前进程的倒计时、到时判定、后台/前台稳定段统一消费这一会话时间。
2. Unity移动端使用`Time.realtimeSinceStartupAsDouble`计量经过时间；单元测试注入经过时间，不修改操作系统时钟。日历显示、今日/七日日期继续使用真实日期入口，不能把整个App的`Now()`简单替换。
3. 剩余显示限定在0～计划秒数，直接时间反例不会再显示85分钟；单调时间同时解决进程内墙钟快进造成提前奖励，不能仅靠显示裁剪修复。
4. 普通杀进程恢复继续使用原截止UTC；若明显回拨导致计算剩余超出计划，先进入恢复选择，允许继续保留的剩余上限或确认中断，不静默发奖励。

**验收：**进程内回拨/快进一小时、timeScale=0、后台/息屏返回都按实际经过时间推进；30秒过去仍只扣30秒。重复完成、截止竞争、普通重启截止恢复不退化。

**边界：**进程死亡并同时改系统时间时，单靠现有本地截止UTC不能辨别全部情况；本批解决进程内计时与可检测异常恢复，不声称实现跨重启防篡改。官方说明确认[Unity移动端系统计时包含睡眠时间](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/time/realtimesincestartupasdouble)；[Android也区分墙钟与含深睡的单调计时](https://developer.android.com/reference/android/os/SystemClock)。实现后仍以模拟器后台/息屏实测为准。

## IA-05 / P1：源码与大资产无法重建当前候选

**修改范围：**当前运行脚本、Prefab/场景、ProjectSettings、Packages、已有资产清单、`docs/DEVELOPMENT.md`及必要交付工具；不把全部历史脏改动视作本次修复。

**修复步骤：**

1. 按最终场景、Animator、UI和动态资源加载点列出实际依赖，复用稳定资产ID及原清单；逐文件区分运行所需、旧参考、私有配置与本地产物。
2. 将运行必需源码、生成器、轻量资源和对应`.meta`按白名单提交main；保留未纳入的用户改动，不全量暂存。
3. 316MB猫网格等必需二进制不直接塞入普通Git。默认准备**运行资产包**作为版本交付附件，保留相对路径和`.meta`，与源码版本对应；优先复用合格已有产物，不复制原始全库。
4. 先核对素材分发权限。可公开资源按[GitHub Releases附件](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)交付；权利不明的资产保持本地/私有，不能因此宣称公开克隆已可完整构建。无哈希门槛。
5. 在一个空验证目录按源码与运行资产包还原，不借用现有Library；开Unity编译、执行核心测试，再产出同一候选。缺资源就保留交付门未通过。

**验收：**依赖无缺项、GUID引用保留、没有私有配置/原始大素材混入；按文档还原后可编译、测试、构建。保留现有MVP与原始母版。大资产公开权限未确认时只完成准备工作，不冒充公开交付完成。

## IA-06 / P2：AI相对模板的收益未证实

**修改范围：**现有评估输入、响应与模板对照，必要的Prompt小改；当前默认不新增模型调用，不引入RAG或长期记忆。

**修复步骤：**

1. 将历史12例真实响应与同场景本地模板匿名、随机排列，固定评分说明：相关性、具体下一步、无越界、无虚构任务、动作合理性。
2. 先做可复算的规则检查，再进行真实人工盲评；代理审阅只能标代理审阅，不能代签真实用户或独立评分者。
3. 同时报耗时、实际返回用量、建议差异与动作分布。12例不报生产P95、不宣称统计显著；不为动作分布均匀而强行随机动作。
4. 如需修Prompt，使用独立保留场景验收，不在原失败目录重跑挑好结果。真实模型调用单独记录版本、次数与预算；最终只在已同意的会后流程请求。
5. 学习意愿/坚持率效果需要后续真实观察。未招募和未完成时维持证据缺口；若无优势，维持AI为可选功能并收窄宣传。

**验收：**能交付盲评输入、规则、实际评分与模板对照，固定安全反例通过，结论与证据相称。完成评估任务不自动等于通过“用户收益”门。

## IA-07 / P2：昵称被当成富文本

**修改范围：**`CatLifeMobileApp.AdoptCat/ShowGrowth/ShowBubble`、命名输入文本、成长页序列化文本绑定与UI生成器。

**修复步骤：**

1. 原始昵称继续按用户输入保存，不简单剥掉尖括号而改变名字。
2. 在现有成长卡的姓名行使用独立纯文本绑定；等级行保留系统固定的颜色格式。卡片与按钮不移动。
3. 同步命名输入的文本组件和含昵称的气泡为纯文本，覆盖所有当前昵称落点。

**验收：**`<b>橘</b>`、不闭合size标签、尖括号和中文昵称均字面显示；重启后原名不变，等级颜色和既定布局保留。实际Game view与模拟器截图确认没有放大、吞字或遮挡。

## IA-08 / P2：Emoji被截断成单个代理项

**修改范围：**`LLMBehaviorSuggestion.SanitizeLine`，并核对同一运行链中的文本长度处理。

**修复步骤：**保留现有长度上限，但截断点落在高/低代理项之间时回退一位，避免产生不完整UTF-16；不增加第三方Unicode库。先修当前实际运行入口，不重写旧模拟Provider。

**验收：**原23中文＋猫Emoji反例不产生孤立代理项；Emoji在开头、边界前后，纯中文、ASCII、空串和三段建议长度控制均通过。完成的目标是合法文本边界，复杂组合字素不在本批扩建范围。

## IA-09 / P2：累计时间先取整导致漏计

**修改范围：**`CatLifeStats.Derive`、记录页七日总数与列表时长格式。奖励和解锁公式不改。

**修复步骤：**

1. 先用秒累计今日、七日及各日数据，再分别转换成分钟；内部累计使用足够容量的整数。
2. 周总数读取七日总秒数的转换结果，不再把已经取整的日柱相加当作精确总数。
3. 明确日柱按日取整、累计总量按原秒合计；在既有说明中表达该差异。记录列表不足一分钟显示秒或mm:ss，避免“总数1分钟、两行全是0分钟”的误解。

**验收：**59+59=1分钟、90+90=3分钟、119+119=3分钟；跨两日59+59的周总数1分钟、日柱各0有明确口径；零记录、统计关闭、跨午夜按结束日、完成/中断奖励和解锁保持原规则。

## IA-10 / P2：宿主停用后客户端busy无法释放

**修改范围：**`MockCatLLMClient`的协程与`UnityWebRequest`所有权，供IA-03调用；不更改所有LLM实现的公共接口。

**修复步骤：**

1. 客户端持有唯一在途协程、传输句柄和请求代次；增加小型`CancelPending(reason)`入口。
2. 当前云端子流程不再另起一个无人统一持有的子协程；由父请求统一拥有，取消时停止整条链并释放传输。
3. 宿主停用时取消并恢复非busy；正常完成、失败、取消只能发出一个终态。旧代次的清理和回调不能释放或覆盖新请求的状态。
4. 仅禁用Behaviour保持旧语义；销毁时清理资源，UI对象已消失时不再投递UI回调。

**验收：**原停用复用红例通过；新增取消后立即重发、旧回调迟到、销毁、真实loopback传输中取消；并发第二次拒绝、首请求完成、429/无效JSON/超时只回调一次等控制继续通过。仍不自动重试。

## IA-11 / P1（发行前）：旧端侧模型存储权限残留

**修改范围：**`Assets/Plugins/Android/AndroidManifest.xml`、旧BlueLm桥的运行参与方式、`CatLifeRuntimeAssemblyValidator`与当前构建校验入口。

**修复步骤：**

1. 当前移动运行Manifest移除`MANAGE_EXTERNAL_STORAGE`、旧`READ_EXTERNAL_STORAGE`和固定`/sdcard`模型路径；旧端侧参考不进入当前运行请求链。
2. 同步旧验证器：当前方案应拒绝上述权限，不再要求它们必须存在。保留非运行参考不等于保留发布权限。
3. 备份策略默认收敛为不自动备份CatLife用户数据：显式配置allowBackup及适用系统的数据提取排除规则，更新本地数据说明；分别检查云备份与设备迁移的实际适用范围，不把一个开关当全部系统均已验证。
4. 最后构建时检查**合并后的APK Manifest**，同时保持review包身份、非debuggable、无摄像头/麦克风/通讯录/SMS权限、网络默认不放开明文。

**验收：**源码与新APK均无旧权限和模型路径；旧SDK验证器不再强制恢复它们；APK静态5项检查通过。声明配置通过不替代系统备份/迁移实测，也不宣称清除了设备上此前已有的备份。

## 最终验收

1. 两轮77项是覆盖基线：全部旧反例与控制场景复测，并新增本方案明确的恢复、取消、时钟和统计边界。入口契约变化时保留原输入与实质行为断言，不能删除反例或放宽断言换PASS；总数按实际执行记录。
2. 独立候选保留MVP。模拟器验证准备→到位→趴卧→专注→结算、恢复、关闭AI、清除、七日与成长；连续运行至少10分钟，读取真实截图/录像。此前Reward信息缺失/黑带、Focus遮爪仍需按原GAP20处理，不能因本表修复就自动关闭。
