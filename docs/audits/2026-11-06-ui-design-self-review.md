# 软件与 GitHub：十条设计规范自查

日期：2026-11-06。检查对象为 CatLife r41 软件，以及 GitHub 展示页 `52b76675` 和三张展示图的 `layout.html` 排版源。本轮是审查，未修改软件、展示图或交互行为。

## 结论

**两端均未达到这套新规范。** 主要缺口是边框与色板、聚焦反馈、暗底字重、文字排版。软件数字字体已有等宽数字；不能因为没有 CSS 属性就认定计时器会抖动。无对应控件的项目不新增功能来凑验收。

| 条目 | Android 软件 | GitHub / 展示图源 | 判断与落地边界 |
|---|---|---|---|
| 1. 去边框、微明度层次、禁纯黑 | **未通过**。候选 Prefab 125 个 Text 中有 76 个不透明纯黑，含隐藏层；按钮、信息卡仍有金色描边。色板是既有奶油白/橙色体系。 | **未通过**。三画板可见 DOM 分别有 5/6/7 个带边框元素，另有伪元素描边。底板为 `#f6f4ed`、`#faf9f4`、`#244b3d`，未采用新中性色板。排版文字无纯黑，但嵌入的软件原图继承软件的黑字。 | 中性容器改用给定浅/暗色层级，以相邻明度分隔；品牌橙/绿用于强调。不能修改软件截图的颜色来冒充软件已经更新。 |

## 修复顺序

1. **先处理软件基础视觉**：去除不透明纯黑与容器描边，建立给定的中性色层次，再补两类输入框的聚焦反馈。维持按钮位置、页面层级、业务与既有资产。
2. **再处理字体与排版**：暗底亮字做实际字重补偿，检查中文末行、图标基线及时间显示。保留已有等宽数字，不做无需求的全项目字体框架迁移。
3. **动效单独按真实场景落地**：先决定会后文字是否需要逐字显现；拖动弹簧不得影响手势逻辑。没有的点赞、复制、折叠场景不新增。
4. **最后同步 GitHub**：先取得新软件候选的真实截图，再更新展示图；可编辑画板去边框、调整色层与字重、启用 tabular-nums/pretty。README 平台级限制继续单列。

这批是新增视觉验收条件，不由此前 152 项功能/页面回归自动覆盖。本轮没有生成新 APK、调用模型或重做猫/小镇。
