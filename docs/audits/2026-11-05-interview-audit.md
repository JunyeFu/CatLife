## 1. 为什么用大模型？怎样证明比普通计时器、本地模板更有价值？

**测试：**离线重算10/9 v2的12个真实响应文件，未重新调用模型。检查HTTP状态、用量、时延、动作分布和建议差异；本轮另跑“统计关闭不编造测量值”和结构化结果显示相关控制测试。

**结果：**12/12历史HTTP200，平均5960.92ms，最长15194ms，13519 tokens；11/12推荐`social_response`，1/12为`quiet_idle`，12条返回建议只有6种完全不同的文本。已有本地模板对照，但没有盲评、真实用户研究或使用行为改善实验。

**IA-06 / P2 / 证据缺口：**模型能返回结果，不足以证明个性化、陪伴效果或学习意愿优于模板。重复文本和集中动作是观察，不能直接等同质量差或统计显著。修复方向：冻结规则基线，以相关性、可执行性、无越界和时延成本进行盲评；用户效果另做真实观察，不能用合成场景代替。

面试时可如实答：核心专注流程是本地确定逻辑，AI只做可选会后建议；目前已证明调用与局部约束可运行，尚未证明用户收益。

## 2. 后台、杀进程、截止瞬间操作，会不会重复奖励或计时漂移？

**测试：**39项EditMode会话/存档/退出手势回归；新增完成后再次完成、JSON恢复后再次完成；复测UI截止瞬间确认中断；注入时间回拨输入。

**结果：**39/39基线通过；新增的重复完成/恢复控制通过；截止瞬间UI操作仍只产生一次完成。**回拨一小时后，25分钟会话返回5100秒（85分钟）剩余时间，断言失败。** 未修改宿主机或设备时间；反例通过控制器时间参数注入。

**IA-04 / P2 / 时间一致性：**`CatLifeSessionController.RemainingSeconds`直接以目标Unix时间减当前时间；`CatLifeMobileApp.Now()`来自设备UTC墙钟。时间调整会延长或提前结算。这是客户端信任设备时钟的限制，不是已发现远程攻击。修复方向：同一进程的计时采用单调时钟；重启恢复继续使用截止时间，并明确处理时钟跳变，不引入服务器计时框架。

## 3. 模型超时、429、乱码、恶意文案和越权动作如何处理？

**测试：**本机`127.0.0.1:25487–25489`注入429、HTTP200无效JSON与超时，执行真实`UnityWebRequest`传输和生产客户端解析路径；加入模型输出命令标志、中文诊断/胁迫文案反例，复测未解锁动作和不完整结构。

**通过：**3/3本机传输用例都只收到一次请求、触发一次错误回调；无自动重试。动作命令标志拒绝、URL拒绝、未解锁动作及不完整结果的本地约束控制通过。未测试真实供应商TLS、限流策略或生产并发。

**IA-01 / P1 / 陪伴内容边界：**以下3条人工注入文案全部被`LLMBehaviorSuggestion.TryBuildSafe`返回`true / passed`，对应3条失败测试：

- “你患有抑郁症，应该停止服药”
- “你太没用了，不继续学我就离开你”
- “我能判断你有焦虑症，这是诊断结果”

对象的安全布尔标志均为false。当前逻辑主要排除英文命令/敏感词与模型自报标志，不能保证中文语义合规；完整三段字段仍会被会后呈现路径接收。这些是注入不可信模型输出后的边界反例，**不是本轮真实模型生成了上述内容，也不是RCE或提示词注入攻击成功的证明**。

修复方向：补充中文诊断、用药与胁迫内容约束及反例集，拒绝不合格文本后保留本地洞察；不把增加几个关键词称为语义安全已全面完成。

## 4. 用户关闭AI、清除记录或存档损坏，数据边界还能成立吗？

**通过：**未同意、AI关闭或中断会话不启动新请求；清除需二次确认且重置领取/同意；清除后的迟到本地回调不能复活旧数据；统计关闭不伪造触控和稳定度。

**IA-03 / P2 / 开关语义：**已有一条`requesting`记录时关闭AI，再注入迟到成功回调，记录仍变为`succeeded`并保存建议，测试失败。`ToggleAi`只改开关，`ApplyAiSuggestion`只检查数据实例身份，没有检查当前开关。这证明旧响应仍入库，**不证明关闭后发起了新上传**；旧请求开始时已经获得同意。修复方向：明确关闭是否应取消在途工作；建议阻止后续呈现/写入，并对可取消请求执行取消。

**IA-02 / P1 / 持久化启动边界：**对真实反序列化入口输入`{`和`null`，均抛出`ArgumentException`，2条失败测试；`{"records":null,"settings":null}`用例通过，不能将其报为缺陷。`Awake`直接使用该反序列化结果且没有错误分支，坏存档可能阻断初始化。本轮复现的是解析层异常并核对启动调用链，未在Android用户存档上制造损坏。

修复方向：解析失败时保留原始存档并提供明确恢复/清除选项；不静默清空。仅针对实际持久化边界处理错误。PlayerPrefs本身不加密，不能将当前本地聚合存储描述为加密隐私保险箱。

## 5. 低多边形为何还有84MiB？别人能克隆运行吗？性能结论凭什么？

**APK检查：**r34为88,202,756 bytes / 84.12MiB，低于120MiB。ZIP条目中未发现原始`.blend/.glb/.gltf`文件；较大的压缩条目包括`libil2cpp.so`约12.01MiB和`libunity.so`约8.77MiB。低多边形只约束几何，包体还包括引擎、原生代码、贴图与其他资源。

**凭据检查：**对197个`assets/bin/Data/`条目共158,093,126解压字节检查`sk-`令牌模式，命中0；这是限定模式检查，不能推出所有秘密类型均不存在。

**IA-05 / P1 / 既有交付缺口：**本地有112个已跟踪文件改动，其中47个位于核心运行脚本/资源/场景范围；运行猫网格`Assets/MobileRuntime/Art/Cat/MSH_CL_CAT_Runtime_v12.asset`本地存在，316,447,903 bytes，但不在Git索引。当前页面和报告已推送，不能替代运行源码与资产交付。克隆当前仓库不能重现本地候选的完整输入。修复方向：按实际依赖整理当前运行源码，明确大资产的交付方式和准备步骤，不将300MiB资源直接混入普通Git提交。

本轮未进行4GB真机或Android性能测试，不能回答“已稳定30fps”；包体合格与性能合格分别判断。
