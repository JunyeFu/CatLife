# CatLife 重做三层开发控制任务包

日期：2026-08-30  
状态：`QA_DRAFT`  
适用范围：基于现有 CatLife 小镇、猫咪、美术规范和功能规划重做 Unity/Android App。

## 1. 控制体系

任务采用大、中、小三层控制：

| 层级 | 控制对象 | 完成定义 |
|---|---|---|
| 大任务包 `BIG` | 一个可独立验收的产品结果 | 对应硬门全部通过，关联中包全部关闭 |
| 中任务包 `MID` | 一个用户可见功能或工程交付面 | AI 效果图、功能描述和验收条件经用户确认 |
| 小任务包 `SMALL` | 可直接执行和验证的原子任务 | 产生明确文件、场景、构建或运行证据 |

控制规则：

1. 中任务包按编号逐个问答确认，不合并询问。
2. 每轮必须包含一张 AI 生成的落地效果图、功能描述、关键交互和一个确认问题。
3. 用户确认后，将该中包从 `WAITING_QA` 更新为 `APPROVED`，再冻结其小任务。
4. 未确认的中包不得进入实现。
5. 验收使用构建报告、运行行为、截图、日志和真机结果；不设置哈希校验门。
6. 原始 `.blend` 只作为视觉母版；移动端使用独立派生资产。

## 2. 总体依赖

```text
  -> BIG-02 移动端美术与界面资产

  -> BIG-04 Android 真机与交付
```

### MID-13 Android 性能与兼容性

状态：`APPROVED`  
问答编号：`QA-13`

确认结论：用户选择 A；保留美术母版库，仅将移动端派生资产放入运行工程；交付一个不超过 `120 MiB` 的离线 ARM64 APK，并由两台真实 Android 设备分别关闭全部性能与恢复硬门。  
确认效果图：`visual-confirmations/QA-13_android-lightweight-device-gate-approved-single-offline-apk.png`

当前核对基线（2026-08-30）：

- 两份现有 APK 均为 `406.06 MiB`；APK 内 `assets` 压缩后为 `383.71 MiB`，其中 `sharedassets0` 为 `378.15 MiB`。
- Unity `Assets` 工作目录约 `8.81 GiB`，其中 `Art` 约 `8.81 GiB`；原始小镇 `.blend` 单文件约 `3.62 GiB`。
- Android 构建已是 ARM64、IL2CPP、引擎代码裁剪和 Managed Stripping Level 2，当前首要问题是运行美术资源体积。
- 当前环境未发现可用 `adb`，模拟器结果不能关闭双真机硬门。

小任务：

- `SMALL-13.01` 建立只包含移动端派生结果的最小 Unity Android 工程；保留 ARM64、IL2CPP 和代码裁剪，不使用下载资源包。
- `SMALL-13.02` 将 Unity/IL2CPP、小镇、猫咪与动画、UI/字体/音频分别控制在 `30/45/15/10 MiB`，保留 `20 MiB` 余量，总 APK 不超过 `120 MiB`。
- `SMALL-13.03` 在 vivo ARM64 和另一品牌 ARM64 真机分别完成全新安装、截图、日志、`gfxinfo` 与 `meminfo` 采证。
- `SMALL-13.04` 每台真机完成三次六秒内冷启动、30 分钟运行、后台返回、杀进程恢复和主页/专注/奖励不低于 30 FPS 的验证，且无崩溃或 ANR。
