# CatLife 从 MVP 到可提交版本：L1 缺口与补齐顺序

日期：2026-09-03
状态：`READ_ONLY_AUDIT_COMPLETE`
范围：只读盘点当前 Unity 工程、MVP APK、已确认 QA-01～QA-14、原始参赛 PPT 与最终提交 PPT；本文件是本轮唯一新增产物，不修改 Unity 实现或既有素材。

## 1. 结论

`CatLife_Mobile_Android_v0.3.0.apk` 应正式降级标记为 **MVP 基线包**，不能再称为可提交候选包。

它已经证明完整小镇可进入、四段会话可运行、记录/成长/设置有基础闭环、MiMo 能在会后完成一次真实请求、模拟器可持续运行且包体低于 120 MiB；但当前产品仍主要是“固定猫咪 + 功能型矩形 UI + 计时器 + 会后一句 AI 文案”。它尚未兑现参赛材料的核心差异化：猫咪自主行为、连续行为识别、心理引导式状态迁移、可被用户感知的大模型决策，以及已确认前端画面。

可提交版本的定义不是“继续给 MVP 加按钮”，而是把以下链路真正接通：

```text
用户行为 -> 本地状态谱 -> 会话状态 -> 猫咪移动/动作 -> UI 反馈
                                      -> MiMo 会后策略 -> 可见建议 + 实际猫咪反应
```

## 4. 必须按此顺序补齐

### L1-01 统一移动运行架构

目标：只保留一个会话真源，把识别、猫咪行为、场景互动作为 `CatLifeMobileApp` 的受控执行器接入，不再让旧系统和移动系统各自运行。

交付：运行时模块关系图、状态/事件契约、当前移动场景装配清单。

硬门 G1：构建场景中能够从同一会话状态读取识别快照，并驱动猫行为；不得出现第二套计时器或第二套会话状态机。

### L1-02 恢复猫咪动作与移动系统

目标：先解决用户已经观察到的“猫咪不可移动”，再扩展情绪和 AI 表现。

必须覆盖：

- 普通状态在可行走区域自主漫游、停留、观察和轻互动；
- 过渡状态靠近或面向用户，再进入坐下/趴下过渡；
- 专注状态停止高活跃漫游，进入安静区域并使用趴下、呼吸、短暂抬头；
- 完成状态起身、靠近或庆祝，随后安全返回普通状态；
- Walk 与 10 个既有动作重新进入统一动作映射；6 个新动作继续作为四状态主链；
- 地标兴趣点、禁走区、路径失败和位置恢复在真实移动场景中工作；
- 动作清单、FBX clips、Animator states 与业务动作 ID 一致。

硬门 G2：模拟器连续观察 5 分钟，猫至少完成“移动—到点—动作—继续移动”循环；四种会话状态均有不同移动强度和动作反馈；无滑步、漂浮、穿模、瞬移或离岛。

### L1-03 接通行为识别与自动进入专注

目标：兑现 PPT 的“不是单纯计时器”，让本 App 内行为真正形成连续状态谱。

必须覆盖：

- 采集本 App 内点击、滑动、停顿、页面切换、猫互动和前后台切换；
- 用滑动窗口生成 `focus_score`、`arousal_score`、`distraction_score`、状态标签和趋势；
- 设置页支持 30 秒/1 分钟/2 分钟适应时长；
- 满足阈值时从普通态进入可取消的过渡提示，再进入专注；
- 隐藏评审层显示真实特征和状态变化，不使用预置动画冒充识别结果。

隐私边界：不采集屏幕内容、输入文本、原始触点、应用包名或跨 App 触控。PPT 中“跨应用触控节奏/后台持续观察”必须改为真实可实现的前后台次数、离开时长和返回间隔，除非以后单独批准系统级权限方案。

硬门 G3：一条可复现模拟器脚本能分别触发“注意偏离—转移中—稳定”三段，并能自动进入专注；记录的只有聚合特征。

### L1-04 还原 QA-01～QA-12 前端

目标：在已有 3D 美术资产上实现已确认画面，不再把纯色矩形 UI 当最终视觉。

必须覆盖：首页、底部准备卡、2 秒 Transition、低刺激 Focus、Reward、记录、成长/猫咪状态、设置/隐私、AI 同意、退出确认、气泡和隐藏评审层。首页必须恢复已确认的视觉层次、圆角按钮、图标化侧栏、气泡和猫/小镇主体关系；记录页使用真实七日图表；猫咪状态页解释当前心情、动作原因和成长进度。

硬门 G4：以相同 1080×2424 画幅逐页对照 QA 确认稿；不是只检查控件存在，而是检查构图、色彩、间距、可读性、遮挡、安全区和状态变化。Home、Setup、Focus、Reward、Records、Growth、Settings 七页全部通过后才能继续。

### L1-05 把 MiMo 变成用户能感知的产品能力

目标：保留已确认的“会后最多请求一次、失败不重试、本地功能独立”，但让请求和结果成为完整体验，而不是结算页附加一行文字。

必须覆盖：

- 结算页显示“正在生成陪伴建议”的明确但低打扰状态；
- 成功结果拆成低压力提醒、任务回归建议、猫咪反应三部分；
- 显示 `MiMo 生成`、实际来源和“仅发送会话聚合值”的入口；
- `recommendedLocalAction` 必须经过本地允许列表后触发一个已解锁的真实猫动作；
- 失败时只显示本地洞察与真实来源，不伪装为云端结果；
- 隐藏评审层能展示本次发送的聚合字段、单次请求状态和被执行的本地动作，不显示凭据。

硬门 G5：同一段 1 分钟会话中，用户能连续看到“请求中—MiMo 建议—猫执行对应动作”；日志证明只请求一次，UI 与日志来源一致。

### L1-06 补齐原 PPT 的其他提交级功能

必须补齐：

1. 首次启动的猫咪领取、命名和基础设置；完成后持久化，后续不重复强制出现。
2. 猫咪状态页：心情、动作说明、成长、爪印、已解锁反馈，不再只显示等级文本。
3. 地标与场景互动：钟楼进入记录、猫屋进入成长，鱼店、奖励树、广场至少各有一种轻交互和猫咪响应。
4. 轻锁定完整表现：隐藏非必要入口、降低画面刺激、降低背景音量、保留上滑确认退出。
5. 完成/中断/后台恢复后的记录、成长和猫状态一致，重启后可恢复。

范围澄清：

- 森林场景已被后续 QA 决策排除；原 PPT 中森林只能标为概念资产，不能宣称已实现“转换场景”。若提交材料继续宣称场景切换，则必须另立新 L1，不得拿小镇地标切换代替。
- 会员、猫咪皮肤、场景主题、学习报告和校园合作版在 PPT 中属于“可拓展商业模式”，不是当前可提交版本的已实现承诺；本阶段不开发商城、订阅或校园后台。
- 活动中心、抽奖、签到、社交排行已被 UI 总规格明确排除，不计入缺口。

硬门 G6：新用户首次流程、日常主页、自动/主动专注、轻锁定、完成奖励、地标互动、记录成长和重启读档形成一条无调试操作的完整用户路径。

### L1-07 生成提交候选与证据

目标：前六门通过后才生成新的版本号和候选 APK；`0.3.0` 永久保留为 MVP 对照，不覆盖。

硬门 G7：

- APK/AAB 不超过 120 MiB，完整离线核心流程可用；
- 模拟器完整回归和至少 10 分钟稳定运行；
- Android 10+、4GB RAM 目标真机完成冷启动、10 分钟运行、后台/重启恢复、AI 联网与离线降级；
- 若沿用 QA-13，则两台真实 Android 设备分别完成性能与恢复验收；
- Home、Setup、Focus、Reward、Records、Growth、Settings、AI 可视化、猫咪移动各有同一候选包的截图或录屏；
- PPT、海报、视频和说明只陈述该候选包已经通过的能力。

## 5. 顺序规则

严格执行：`G1 -> G2 -> G3 -> G4 -> G5 -> G6 -> G7`。

- 不先美化一个仍然没有真实状态输入的假 AI 面板。
- 不先接 MiMo 猫动作建议，再补猫动作执行器。
- 不因页面截图好看就跳过猫咪移动、识别或持久化验收。
- 不以旧代码文件存在、Editor 截图、模拟数据或 AI 概念图代替 APK 中的真实功能。
- 每个 L1 通过后再拆成对应的中任务与小任务；未通过当前硬门，不启动后续 L1 的正式合并。

## 6. 下一步唯一入口

下一轮从 **L1-01 统一移动运行架构** 开始，先建立当前移动场景的组件接线图和唯一状态/事件契约；随后立即进入 **L1-02 猫咪动作与移动系统**。在 G2 关闭前，不再把任何新 APK 称为可提交候选版。
