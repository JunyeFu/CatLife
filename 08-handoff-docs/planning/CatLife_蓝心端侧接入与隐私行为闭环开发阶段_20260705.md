## 2. 蓝心大模型接入决策

最终主路径：

```text
Unity 聚合行为特征
 -> PrivacyGateway
 -> Android BlueLmUnityBridge
 -> LlmManager.init / generate
 -> BlueLM 3B 端侧模型
 -> JSON 输出
 -> Unity 安全解析
 -> CatBehaviorDriver 高层建议消费
 -> 本地猫咪移动 / 动画 / 气泡执行
```

备用路径：

```text
Unity -> 自有服务端代理 -> https://api-ai.vivo.com.cn/v1/chat/completions
```

```text
Unity LocalTemplateFallback
```

## 3. 隐私边界

允许进入识别和 LLM 的只有聚合、去标识化、枚举化数据：

- CatLife 内按钮类型、页面枚举、场景交互标签。
- 点击/滑动/停留的计数、分桶或时长。
- 专注开始、取消、完成、上滑解锁。
- 猫咪点击、长按、场景点点击。
- 用户明确授权后的 CatLife 自身离开/返回时间点和间隔。
- 猫咪当前高层状态、当前动画语义、近期场景标签。

禁止采集、传输或让模型请求：

- 输入框原文、聊天内容、网页内容。
- 截图、录屏、OCR、剪贴板。
- 联系人、短信、相册、麦克风、摄像头、精确位置。
- App 包名、App 列表、跨 App 内容。
- 原始触摸坐标、原始触摸轨迹。
- Transform、NavMesh、Animator、Physics、坐标或速度命令。

所有 LLM 输入输出都必须经过：

```text
BehaviorEventSanitizer / PrivacyGateway 输入校验
 -> BlueLmJsonGuard Android 侧校验
 -> LLMBehaviorSuggestion / FocusFeedbackLlmOutput Unity 侧解析
 -> PrivacyGateway 输出校验
 -> 不通过则 LocalTemplateFallback
```

## 4. 当前接口适配原则

第二份蓝心文档给出的代码是目标结构，但当前工程已经有一套接口，落地时必须优先适配现有代码，不能机械复制导致编译破坏。

当前 `ICatLLMClient` 形态：

```csharp
bool Enabled { get; }
bool IsBusy { get; }

void RequestSuggestion(
    CatPromptContext context,
    CatPromptBuilder builder,
    Action<LLMBehaviorSuggestion> onSuccess,
    Action<string> onError);
```

因此新增 `BlueLmOnDeviceClient`、`VivoCloudOpenAiClient`、`LocalTemplateLLMClient` 或 `LlmClientFactory` 时，必须遵守现有接口，或先做一次小范围接口迁移并同步更新 `MockCatLLMClient`、`FocusFeedbackProvider`、`CatBehaviorDriver` 和验证器。

建议采用保守方案：

1. 保留现有 `ICatLLMClient` 签名。
2. 新增 `BlueLmOnDeviceClient : MonoBehaviour, ICatLLMClient`。
3. 新增 `LlmRuntimeMode` 和 `LlmClientFactory`，但输出仍是现有 `ICatLLMClient`。
4. `FocusFeedbackProvider` 继续负责节流、fallback 和安全状态记录。
5. `CatBehaviorDriver` 只消费 `LLMBehaviorSuggestion` 的三个权重、`showBubble` 和短句，不新增坐标/动画命令入口。

目标：

- 在 Android 侧和 Unity 侧双重约束输入输出。
- 让 BlueLM 只输出严格 JSON，不输出 Markdown 或解释。

输出 JSON 必须包含：

```json
{
  "version": "catlife.bluelm.feedback.v1",
  "suggestedLine": "不超过24个汉字",
  "showBubble": false,
  "moodBias": "quiet",
  "roamWeightBias": 0.0,
  "quietIdleWeightBias": 0.0,
  "socialResponseWeightBias": 0.0,
  "recommendedLocalAction": "none",
  "rawTextRequested": false,
  "coordinateCommandIncluded": false,
  "animatorCommandIncluded": false,
  "navMeshCommandIncluded": false,
  "transformCommandIncluded": false,
  "privacyInferenceIncluded": false
```

验收：

- 含 `Animator`、`NavMesh`、`Transform`、`position`、`camera`、`microphone` 的输出被拒绝。

阶段 3 实际落地说明：

- 当前 Android 插件采用 Java 骨架，因此本阶段文件使用 `.java`，不是 `.kt`。

- 输出 guard 只扫描 `suggestedLine` 和安全布尔位，避免把 `coordinateCommandIncluded=false` 这类安全字段名误判为命令输出。

### 阶段 4：BlueLM generate 闭环

目标：

- 完成 `LlmManager.generate(prompt, TokenCallback)` 到 Unity 的结构化建议闭环。
- 让端侧模型成功时产生一次真实 JSON 建议。

关键实现：

- Android `BlueLmEngine.generateJsonAsync(requestId, contextJson, callback)`。
- TokenCallback 累积 token，结束后抽取第一个 `{...}` JSON。
- Android 侧先用 `BlueLmJsonGuard.isSafeOutput()` 检查。
- Unity 侧再用 `LLMBehaviorSuggestion` 和 `PrivacyGateway` 检查。

验收：

- Unity 收到 payload 后能更新 `LastSource=bluelm_on_device` 或等价状态。
- 断网不影响端侧主路径。
- generate 超时、异常或输出不合规时，猫咪仍正常移动、播放动画和显示本地气泡。

### 阶段 6：CatBehaviorDriver 消费蓝心建议

目标：

- 让 BlueLM 输出只影响行为权重、气泡和本地动作类别。
- 保持猫咪位置、导航、动画由 Unity 本地规则最终决定。

允许消费：

- `roamWeightBias`
- `quietIdleWeightBias`
- `socialResponseWeightBias`
- `showBubble`
- `suggestedLine`
- `recommendedLocalAction`

本地映射：

| `recommendedLocalAction` | 本地行为 |
|---|---|
| `none` | 不强制动作，只应用权重 |
| `quiet_companion` | 提高静止/低扰动倾向，专注态少气泡 |
| `gentle_return` | 可排队轻提醒，不责备用户 |
| `reward_after_focus` | 仅在完成专注后触发奖励倾向 |

禁止：

- `agent.SetDestination(llmOutput.coordinate)`
- `animator.Play(llmOutput.animatorState)`
- `transform.position = llmOutput.position`
- 根据模型输出直接修改 NavMesh、Collider、Camera 或 Physics。

验收：

- Normal 状态模型可提高 warm/curious 倾向。
- Focused 状态模型只提高 quiet/calm，气泡低频或隐藏。
- DistractedReturn 状态可以出现温和短提醒。
- Reward 状态可以触发奖励语气，但不强制播放具体 Animator state。

### 阶段 7：云端 API 备用路径

目标：

- 比赛长期主线仍只把云端 API 作为开发期和非云真机环境备用。
- 真实版/最终提交 APK 的要求是“安装到云真机后可直接调用真实 API”，因此允许本机导出的真实版 APK 内置云真机可用 key。
- 不把 vivo AppKey 写入 GitHub、代码包、可提交示例文件、日志或公开文档。
- 使用截图补充的 vivo AppID `2026414599` 作为服务端代理配置项。

实现要求：

- 真实版 APK 短期路径：`MockCatLLMClient` 通过 `VivoCloudDemoConfig` 读取本机私密 Resources 配置，直接请求 `https://api-ai.vivo.com.cn/v1/chat/completions`。
- 正式公开/代码包路径：后续新增 `VivoCloudOpenAiClient` 时应只请求自有代理，代理再调用 vivo 云端 API，避免 AppKEY 长期进入客户端。
- 公开代码包默认没有私密配置；缺少私密配置时自动 fallback。
- 云端输出同样经过 `LLMBehaviorSuggestion` 和 `PrivacyGateway`。
- AppKEY 只允许配置在服务端代理或本机未跟踪配置中，例如 `VIVO_APP_KEY`、`CATLIFE_VIVO_APP_KEY`、CI Secret 或 Android/Unity 本机 `local.properties`，不得进入 Git。
- 文档、日志和截图中只允许展示 AppID、密钥来源、配置变量名和脱敏状态，不展示 AppKEY 明文。
- 当前为方便直接导出真实版 APK 并安装到云真机，Unity 会读取本机未跟踪资源 `Assets/Resources/CatLifePrivate/vivo_cloud_credentials.json`；该目录已加入 `.gitignore`，会进入本机导出的真实版/最终提交 APK，但不会提交到 GitHub。
- 可提交示例文件位于 `Assets/Configs/vivo_cloud_credentials.example.json`，只保留 AppID、API 地址、模型名和占位 AppKEY。
- 现有场景中仍引用 `MockCatLLMClient`，该客户端已设计为“检测到本机 vivo 云端凭据则优先真实调用，失败自动回退本地 mock”，避免为演示导出重新改场景序列化引用。
- 当前代码实现位置：`Assets/Scripts/LLM/VivoCloudDemoConfig.cs` 和 `Assets/Scripts/LLM/MockCatLLMClient.cs`。

验收：

- 未配置本机私密 Resources 或代理时自动 fallback。
- 配置本机私密 Resources 或代理后可完成一次结构化 JSON 调用。

### 阶段 10：PPT 与交付材料同步

目标：

- 把工程能力和 PPT 表述对齐，避免过度承诺。

应使用表述：

```text
CatLife 的正式目标路径优先使用蓝心端侧 3B 模型，在 vivo 云真机本地推理。
当前真实版/最终提交 APK 已加入 vivo 云端 API 演示配置：检测到本机私密配置时优先调用真实云端模型，失败时自动降级到本地模板，保证演示可运行。

模型输出严格 JSON，只包含短句、气泡开关和少量行为权重偏置。
猫咪移动、路径、动画和交互频率仍由 Unity 本地规则控制。

```

禁止表述：

- 已读取用户跨 App 内容。
- 已读取用户输入文本、截图或 OCR。
- 大模型直接控制猫咪坐标、动画或 NavMesh。
- 已完成森林场景。
- 只接通云端 API 时，不写“蓝心端侧 SDK 已完成”。
- APK 真机验证未完成前，不写“已完成真机验证”。

## 6. 最小可提交版本定义

本轮 BlueLM 与识别模块最小可提交版本必须满足：

1. Unity Editor 下仍能完整运行小镇主场景和猫咪行为。
2. Android APK 可构建并安装到 vivo 云真机。
3. 蓝心端侧模型可 init；失败时不崩溃并 fallback。
4. 至少一次端侧 `generate` 或 vivo 云端 API 返回结构化 JSON；若失败，保留清晰失败码与 fallback 证据。
5. Android 去标识化行为事件能进入 Unity `RealtimeFeatureEngine`。
6. 隐私违规输入/输出在 Unity 和 Android 双端都被拦截。
7. LLM 输出只影响权重、气泡和本地动作类别。
8. 专注状态下猫咪低扰动，非专注状态下更活泼。
9. 断网、未授权、SDK 初始化失败、模型输出不合法时，App 仍可运行。
10. 有 `adb logcat`、screenrecord、Unity validator 或 Play Mode 长跑证据。

## 7. 下一轮推荐执行顺序

推荐下一轮从低风险到高风险执行：

1. 阶段 0：确认基线和当前接口。
2. 阶段 1：Unity BlueLM adapter 骨架，先保证 Editor 不坏。
3. 阶段 3：补 JSON schema 和 PrivacyGateway 输出白名单，因为这是所有接入的安全前置。
4. 阶段 2：Android Plugin 骨架和权限配置。
5. 阶段 4：端侧 generate 闭环。
6. 阶段 5：Android 行为事件桥。
7. 阶段 6：CatBehaviorDriver 消费模型建议。
8. 阶段 7：确认真实版/最终提交 APK 内置本机私密 vivo 云端配置和云真机可用 key，并执行一次真实调用或明确 fallback。
9. 阶段 8：Splash 可在验收前后独立补，不阻塞云端 Demo 或 BlueLM 主链路。
10. 阶段 9：云真机 APK 验收；通过后进入阶段 10 同步 PPT、视频脚本和最终提交材料。

如果开发时间不足，优先保住：

```text
端侧 init/fallback
 -> 端侧 generate 一次结构化 JSON
 -> 隐私输入输出拦截
 -> APK 云真机可运行证据
```

这四项比扩展更多猫咪互动、更多 UI 页面或森林场景更关键。
